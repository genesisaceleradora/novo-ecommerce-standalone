# 00 — Contexto do Projeto

## O que estamos criando

Um novo ecommerce standalone, em código próprio, para vender produtos ainda não definidos.

Este projeto deve usar a estrutura comercial, visual e estratégica que já funcionou no ecommerce Eternize como referência provisória, mas sem copiar nome, domínio ou produto final.

## Decisões já tomadas

```txt
Nome do projeto: A definir
Produto principal: A definir
Domínio local: http://localhost:3000
Gateway de pagamento: Pagar.me
Base44: Não usar
Stack: Next.js + TypeScript + Tailwind
Desenvolvimento: Codex + GitHub
Deploy futuro: Vercel
Banco sugerido: Supabase/PostgreSQL
Storage sugerido: Supabase Storage, S3 ou Cloudflare R2
```

## O que deve ser herdado da Eternize

Como ainda faltam informações específicas, use a Eternize como blueprint para:

- Estrutura de páginas.
- Estética premium e emocional.
- Seções comerciais.
- Organização de produtos e categorias.
- Blocos de benefício.
- FAQ.
- Fluxo de personalização.
- Tracking e eventos.
- Modelo de páginas por nicho/categoria.
- Cuidados com SEO.
- Estrutura de imagens para desktop e mobile.

## O que NÃO deve ser herdado automaticamente

- Nome Eternize.
- Produto luminária, caso o novo projeto seja outro produto.
- Domínio real.
- Logos ou marca final.
- Preço definitivo.
- Dados que possam parecer prova real sem confirmação.

## Objetivo comercial

Criar um ecommerce preparado para vender com tráfego pago, SEO e campanhas sazonais.

O site deve ser:

- Rápido.
- Bonito.
- Responsivo.
- Premium.
- Fácil de comprar.
- Fácil de editar.
- Preparado para produtos personalizados.
- Preparado para checkout com Pagar.me.
- Preparado para escalar em múltiplas categorias.

## Filosofia do projeto

Primeiro criar uma base vendável e confiável. Depois evoluir painel, automações, integrações e personalizações avançadas.

Não começar pelo complexo. Começar pelo que vende.
